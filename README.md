# Repository Setup
Provisioning and initialization of the official version control environment (e.g., GitHub/GitLab), including .gitignore, branch protection rules, and access permissions.

The official repository is hosted on GitHub. The team will protect `main`, require pull requests and one non-author approval, require conversation resolution, prevent force pushes and branch deletion, and delete merged branches automatically. Required automated checks will be added after the implementation stack is selected. All three team members require repository access appropriate to their responsibilities.

# Contribution Guide
Documentation defining repository workflow standards, branch naming conventions, pull request procedures, code review requirements, and commit message formats.

The complete workflow is maintained in [`CONTRIBUTING.md`](CONTRIBUTING.md).

* **Repository Workflow Standards:** GitHub issues, short-lived branches, pull requests, review, then squash merge.
* **Branch Naming Conventions:** `<type>/<issue-number>-<short-description>` in lowercase kebab-case.
* **Pull Request Procedures:** One focused outcome, linked issue, completed template, and recorded validation.
* **Code Review Requirements:** At least one approval from a team member other than the author.
* **Commit Message Formats:** `<type>(optional-scope): <imperative summary>`.
